# Install judgment before you install skills

The highest-return move in October 2026 is not another skill pack. Freelance demand for AI work is genuinely large — Upwork's AI category passed **$300M annualised Gross Services Volume, up ~50% year on year**, with AI integration and automation growing **over 90%** — but the median posted AI rate is **$27.50/hour** and **85% of hourly AI postings pay under $50** ([GigRadar](https://gigradar.io/blog/upwork-market-report-2026); [Upwatcher](https://www.upwatcher.io/market/ai/)). Open-source contribution is simultaneously drowning in plausible-but-wrong output: **25% of incoming pull requests are estimated to be low-quality "AI slop"** and **53% of maintainers disagree that generative AI has improved community trust** ([LF Research, 20 Oct 2026](https://www.prnewswire.com/news-releases/new-lf-research-survey-shows-generative-ai-cuts-open-source-coding-time-in-half-but-25-of-incoming-pull-requests-are-considered-ai-slop-302913843.html)). Both markets price the same scarce good — verified reduction of someone else's uncertainty — and neither pays for the number of skills you have installed. The most-installed skill in the ecosystem, `find-skills`, has **4.0M installs**, while a large-scale audit found **26.1% of skills contain at least one vulnerability** and skills that bundle scripts are **2.12× more likely** to be vulnerable ([skills.sh](https://www.skills.sh/); [arXiv 2601.10338](https://arxiv.org/abs/2601.10338)). Popularity tells you what is easy to install. Capability tells you what survives contact with a client's acceptance criteria or a maintainer's review queue. This report separates the two, ranks each market twice, and gives a subtraction-first stack and a 90-day plan for an OpenCode user who already has 76 global skills.

## Popularity is installer telemetry, not evidence of capability

Six different objects get blurred together in "AI agent skills" discourse, and the blur is where most bad purchasing decisions happen. An **installable agent skill** is a folder with a `SKILL.md` file: YAML `name` and `description`, markdown instructions, optional scripts and references, loaded by progressive disclosure so only the description sits in context until the skill fires ([agentskills.io](https://agentskills.io/home)). An **MCP server** is a typed tool surface with authentication and a runtime; it fails loudly with schema errors where a skill fails quietly with a skipped step ([decodo](https://decodo.com/blog/claude-skills-vs-mcp)). A **plugin** is a host-bound bundle — Claude Code marketplaces, Codex plugins, Cline plugins, OpenClaw's ClawHub — that is convenient but does not port. An **agent framework** is a programming library for building agents: LangChain, LangGraph, CrewAI, Microsoft Agent Framework, OpenAI Agents SDK, Pydantic AI, Google ADK ([LangChain 1.0](https://www.langchain.com/blog/langchain-langgraph-1dot0); [Microsoft](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). A **coding agent or harness** is the thing you actually talk to: Claude Code, Codex, OpenCode, Cline, Goose, Kilo ([OpenCode](https://github.com/anomalyco/opencode)). And **human skills** — scoping, writing acceptance criteria, reading a diff, judging what not to submit — cannot be installed at all.

The evidence that popularity diverges from capability is unusually strong for a young ecosystem. Install counts are anonymous, deduplicated CLI telemetry, and a single repo install can count once per skill it contains, so counts measure bundle weight rather than users or quality ([skills.sh docs](https://www.skills.sh/docs)). Stars are worse: an ICSE 2026 study found roughly **6M suspected fake stars across 18,617 repos**, with AI/LLM repos the second-largest category at **16.6%** ([ICSE](https://dl.acm.org/doi/10.1145/3744916.3764531)). The head of the install market is not billable capability — it is engineering-process packs and viral media generators. Of the top 100 skills, **30 are workspace-app connectors, 22 are cloud/vendor platforms, 20 are dev workflow, 12 are media generation, and only 2 are marketing/sales**; the top three publishers hold **67.9% of installs** ([Pro Skill Packs](https://proskillpacks.github.io/study/top-skills/)). Meanwhile the skills that map to client deliverables — documents, design, verification — sit in the **100K–1M** band, an order of magnitude below the leaders ([skills.sh/anthropics](https://www.skills.sh/anthropics/skills)).

The controlled evidence is more sobering than the leaderboards. SkillsBench found curated skills lift average pass rates from **33.9% to 50.5% (+16.6 percentage points)** across 18 model–harness configurations, but a later revision with 7,308 trajectories found only **+4.5 points for software engineering** versus **+51.9 for healthcare**, with **16 of 84 tasks showing negative deltas** and self-generated skills producing **no average benefit (−1.3 points)** ([arXiv 2602.12670](https://arxiv.org/abs/2602.12670); [SkillsBench PDF](https://yubol-bobo.github.io/assets/pdf/SkillsBench.pdf)). With 34,000 skills to retrieve from, "the benefits of skills are fragile" and pass rates approach no-skill baselines ([arXiv 2604.04323](https://arxiv.org/html/2604.04323v1)). Retrieval precision collapses from **29.6% actual-use precision at 5 candidates to 3.3% at 100** ([arXiv 2608.14036](https://arxiv.org/html/2608.14036)). Across 5,832 runs, **553 gain transitions were offset by 324 regressions — 59% of gross gains cancelled** — a "regression tax" with no library condition showing zero regressions ([arXiv 2607.22520](https://arxiv.org/abs/2607.22520)). And Vercel's Next.js eval found a documentation skill was **never invoked in 56% of cases** and scored the same 53% as no documentation, while an 8 KB index in `AGENTS.md` scored 100% ([Voyager](https://voyager.so/blog/mcp-vs-skills)). The practical reading: a large global library is a retrieval and security liability before it is an asset.

## Freelancing pays for accountability at a $27.50 median and a $180 ceiling

The freelance market is barbelled, and the middle is hollow. At the bottom, **55% of fixed-price AI postings are under $250** — one-off prompt tweaks, single-bot setups, "fix my n8n flow" tickets — while at the top, specialist agent developers bill **$800–$2,500/day**, with senior bands at **$180–$250/hour** and domain specialists in legal, medical and financial AI at **$220–$350/hour** ([Upwatcher](https://www.upwatcher.io/market/ai/); [AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide)). The median tells the real story: **P25 $19, median $27.50, P75 $40, P90 $60**, with only **157 hourly postings above $75** and **18 above $150** in a 2,254-posting sample. An independent index of 690 scored postings puts medians at **$20/hour** for "AI agents", n8n and API integration, **$16** for workflow automation and MCP, **$38** for Claude and React, and **$12** for LangChain, multi-agent and OpenAI API work ([AgentScout](https://agentscoutjobs.com/rates)). The gap between $27.50 and $180 is not the same work selling at different prices on the same platform. It is selection: open listings attract price-anchored buyers and template bidders, while high-end work moves through referrals, vetted networks and agencies.

Demand is concentrated in wiring, not modelling. In a May 2026 scrape of **5,536 AI-tagged Upwork postings**, "AI agent development" appeared on **814 (14.7%)**, ahead of machine learning at **744 (13.4%)**; Python led at **24.9%**, API integration at **11.3%**, automation at **9.2%**, n8n at **6.5%** ([Upwatcher](https://www.upwatcher.io/market/ai/)). The contract shape is mid-skill and part-time: **63.2% hourly**, modal commitment **30 hours/week**, modal duration **1–3 months**, and experience tier requested **Intermediate 3,218 versus Expert 2,102 and Entry 216**. That is the worst possible structure for a new entrant — the volume is exactly where competition is fiercest. Upwork's own data shows the AI/ML subcategory is "over-fished" at a **7.21% reply rate versus a 7.45% platform mean**, while Information Security & Compliance replies at **11.21%** and Product Design at **10.78%** ([GigRadar](https://gigradar.io/blog/upwork-market-report-2026)).

What clients actually buy is narrower and more operational than the category names suggest: **AI integration into existing tools, support and sales chatbots, custom AI apps, workflow automation, n8n workflows, Claude-based builds, rapid "vibe-coded" prototypes, AI consulting, and AI-generated video** ([Upwork](https://www.upwork.com/resources/upwork-hourly-rates)). The durable engagement is sold in stages — **paid discovery of 4–8 hours at $500–$1,200, a time-and-materials prototype, a fixed or milestone production build, evaluation and red-teaming budgeted at ≥20% of build cost, then a retainer at $3K–$8K/month** ([AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide)). Two practitioner rules follow. Budget **2–3×** for prototypes because probabilistic behaviour makes scoping unpredictable, and sell the retainer because agents drift with model and data changes. The build is a project; reliability is an annuity.

Tool stacks correlate with rate only indirectly. In posted-rate data, **LangChain and "multi-agent" sit at the bottom ($12/hour)**, while **React and Claude sit at the top of the technical tags ($38)** and **security at $30** ([AgentScout](https://agentscoutjobs.com/rates)). Upwork's own category page prices **ML Engineers at $50–$200** and **Data Scientists at $35–$250**, well above **AI Developers at $30–$50** and **AI Engineers at $35–$60** ([Upwork](https://www.upwork.com/resources/upwork-hourly-rates)). The pattern is consistent: frameworks are table stakes that every bootcamp graduate claims, and model vendors keep absorbing them. Premiums attach to things that are expensive to get wrong — **permissions, audit trails, evaluation, data access, uptime, and vertical domain rules**. The most actionable adjacent signal is the web product stack: TypeScript grew **75% week on week** and Next.js **56.2%**, and business process automation **145.5%**, which points to AI embedded in shipping software rather than standalone agents ([Upwatcher](https://www.upwatcher.io/market/ai/)). MCP is the interesting contradiction: clients increasingly specify MCP compatibility, yet MCP postings clear at a **$16 median** — in-demand and well-paid are not the same claim ([AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide); [AgentScout](https://agentscoutjobs.com/rates)).

Saturation is therefore predictable. **Saturated:** generic "AI developer", prompt engineering, single-bot builds, n8n repairs, LangChain demos, AI content and design. **Emerging:** production reliability and evals, agent security and permissions, MCP integration done properly, vertical agents, and AI inside shipping web products. The economics reinforce it: Upwork replaced its flat 10% fee with a **0–15% variable fee** in May 2025, Connects cost **$0.15** each with typical bids around **12**, and one analysis estimates an effective **13–16% tax for targeted teams and 28–34% for high-volume bidders** ([GigRadar](https://gigradar.io/blog/upwork-market-report-2026)). Only **51.9%** of AI postings come from payment-verified clients ([Upwatcher](https://www.upwatcher.io/market/ai/)). Commoditisation, not platform policy, is the binding constraint.

## Open source rewards uncertainty reduction, not code volume

Maintainers are not short of patches. They are short of review time and trust. Evidence grades from the notes are preserved in this section: **[P]** primary project or foundation document, **[R]** peer-reviewed or preprint research, **[S]** secondary or vendor reporting, **[A]** individual anecdote. The Linux kernel's AI policy is the clearest statement of the exchange rate: an AI-assisted workflow must read the process docs, locate the commit, **build a reproducer for any non-trivial bug**, write the fix, build and verify it, pass `checkpatch.pl`, add a `Fixes:` tag, find maintainers with `scripts/get_maintainer.pl`, and explicitly state what could not be built or tested — because "maintainers currently waste too much time analyzing unverified reports and untested fixes" (**[P]** [Linux kernel docs](https://docs.kernel.org/process/coding-assistants.html)). curl states the general rule: "a contribution should be worth more to the project than the time it takes to review it, which is usually not the case if large parts of your PR were written by LLMs" (**[P]** [curl policy](https://curl.se/dev/contribute.html#on-ai-use-in-curl)). Google Summer of Code tells contributors the human retains **100% responsibility**, that AI belongs on research and "grunt work", and that the contributor must define test scope (**[P]** [GSoC](https://developers.google.com/open-source/gsoc/resources/ai_guidance)).

The empirical picture matches the policies. AIDev aggregates **932,791 agent-authored pull requests across 116,211 repos and 72,189 developers**, with a curated subset of **33,596 PRs in 2,807 repos** above 100 stars (**[R]** [arXiv 2602.09185](https://arxiv.org/abs/2602.09185)). An EASE 2026 study of that data found most AI-generated PRs receive **no review at all**, and when they are reviewed, **AI agents dominate rather than humans** (**[R]** [arXiv 2605.02273](https://arxiv.org/abs/2605.02273)). Kubernetes' experience is instructive because it is a success story: CodeRabbit worked as a **contributor pre-review quality gate**, not an approver, with a label for unresolved AI comments; Copilot was limited because only maintainers could request reviews (**[P]** [Kubernetes blog](https://kubernetes.io/blog/2026/06/26/open-source-maintainership-in-the-age-of-ai/)). That is the correct mental model everywhere: **agent review is a filter that reduces obvious defects, never evidence that a human reviewed the change.**

High-leverage tasks rank by how much uncertainty they remove per minute of maintainer attention, not by technical difficulty. First, **reproduce and minimally fix a confirmed bug with a regression test**. Second, **add missing tests** to existing behaviour in the project's preferred style. Third, **triage**: dedupe issues, confirm versions and environments, bisect. Fourth, **docs, examples and changelog corrections** tied to released behaviour. Fifth, **CI, dependency and tooling maintenance** that removes toil. Sixth, **small features already agreed in an issue**. Seventh, **security fixes only through private channels with a reproducer**. The worst-received work is the large "complete" PR, the speculative refactor, the formatting-only churn, and the automated vulnerability report — even when technically correct. curl's bug bounty ended in January 2026 after "death by a thousand slops" in vulnerability reports ([Stenberg](https://daniel.haxx.se/blog/2025/07/14/death-by-a-thousand-slops/); [LWN](https://lwn.net/Articles/1055996/)).

Project selection matters more than tool selection. **Tier 1 — explicit allow, disclosure format, strong CI, review capacity:** Kubernetes, several Apache projects (Airflow, Arrow, DataFusion), the Linux kernel, Fedora, Firefox, Rust, and the Python scientific stack (CPython, NumPy, SciPy, pandas, pytest). **Tier 2 — allowed but strict or ambiguous:** LLVM, which permits AI with disclosure but **forbids it on "good first issues"**, plus NetBSD, IREE and Mesa ([LLVM](https://llvm.org/docs/AIToolPolicy.html)). **Tier 3 — prohibited:** Zig, Godot (after a 2026 policy change), QEMU, OpenJDK, Servo, Asahi Linux, Gentoo and several GNOME apps (**[P]** [policy catalogue](https://github.com/melissawm/open-source-ai-contribution-policies); [Godot](https://godotengine.org/article/contribution-policy-2026/)). The catalogue itself warns its classifications are "in many cases, inadequate", and policies moved repeatedly in 2026 — re-check before every contribution (**[S]** [GitHub](https://github.com/melissawm/open-source-ai-contribution-policies)).

Disclosure is converging on a standard but is not standardised. The kernel requires `Assisted-by:` and forbids agents from adding `Signed-off-by` because only humans can certify the DCO. Kubernetes allows `Assisted-by:` and disallows `Co-developed-by:`. The Apache Software Foundation recommends `Generated-by: <Tool> <Version>` and requires contributors to verify that tool terms permit Apache-2.0 distribution, noting that ICLA §7 is "not a practical route" for AI output (**[P]** [ASF](https://www.apache.org/legal/generative-tooling.html)). Homebrew allows only **one AI-assisted PR open at a time** (**[P]** [Homebrew](https://github.com/Homebrew/brew/blob/main/CONTRIBUTING.md#artificial-intelligencelarge-language-model-aillm-usage)). The disclosure that earns trust is specific and bounded — "used Claude Code to draft the test and initial patch; I reproduced the bug, rewrote the fix, and ran `make test` and `checkpatch.pl`" — not "AI-assisted".

Star counts (**[S]** popularity signals, not efficacy) from [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) and the [GitHub API table](https://api.github.com/repos/obra/superpowers); process details from [Superpowers](https://github.com/obra/superpowers); platform mechanics from [GitHub Docs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review).

Three design properties separate the powerful OSS skills from the popular ones. They encode **evidence-based exit criteria** — tests passing, build output, runtime data — rather than style opinions. They include **anti-rationalization tables** naming the excuses agents use to skip steps, which is a direct response to the failure mode maintainers describe. And they ship **verification**, not just procedure: `constraint-driven-development` exists specifically because agents optimise for green CI by disabling the check ([addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)). One security detail deserves more attention than it gets: GitHub Copilot code review reads instructions and skills from the **PR head branch**, not the base branch, so a contributor can alter the reviewer's behaviour in the same PR ([GitHub Docs](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review)). Maintainers should treat changes to `AGENTS.md`, `.github/skills` and instruction files as security-relevant diffs; contributors should not touch them in a feature PR.

A new contributor should start with **triage and reproduction in a Tier 1 project**, not with a feature. Pick a repo with a written AI policy, a `CONTRIBUTING.md` containing test and build commands, an issue-first norm, and recent maintainer activity. Reproduce one open bug on the current default branch, post the reproduction steps with version and environment, then submit the smallest patch that makes a failing test pass. One PR open at a time. Disclose precisely. Close your own abandoned work. That sequence produces the two things that compound: merge history and maintainer recognition. It also produces the cheapest freelance portfolio available, because a merged fix with a regression test is a public, verifiable work sample in a market where most agent work is proprietary and cannot be shown ([AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide)).

## The ecosystem consolidated around MCP and a thin harness

Attention and engineering adoption have decoupled. By stars, the leaders are **OpenClaw at 392,764**, **Superpowers at 303,598**, **Hermes Agent at 256,178**, **OpenCode at 220,087**, **n8n at 208,340**, **Dify at 159,266**, **Langflow at 155,921**, **Claude Code's public repo at 152,884**, and **LangChain at 148,277** ([GitHub API](https://api.github.com/repos/openclaw/openclaw); [LangChain](https://api.github.com/repos/langchain-ai/langchain)). By downloads, a different order appears: **LangChain at 170.5M PyPI downloads/month**, LangGraph at **44.8M**, Strands at **37.1M**, OpenAI Agents at **12.4M**, Google ADK at **10.1M**, Pydantic AI at **5.4M**; on npm, the **MCP SDK at 256.8M/month**, Vercel's AI SDK at **118.6M**, Codex at **91.5M**, Claude Code at **49.1M**, and `opencode-ai` at **11.6M** ([pypistats](https://pypistats.org/api/packages/langchain/recent); [npm](https://api.npmjs.org/downloads/point/last-month/@modelcontextprotocol/sdk)). Stars measure attention. Downloads measure plumbing. The plumbing layer is MCP.

Survey data gives the best independent read on who actually uses what. Stack Overflow 2026 (n=17,464) found **83% use at least one AI tool, 65.9% use coding assistants or agents, but only 26.2% use agents or automated workflows**; among coding-agent users, **Claude Code 65.5%, Copilot 58.7%, Codex 29.5%, Cursor 25.5%, Antigravity 16.0%, Gemini CLI 14.6%, OpenCode 13.6%** ([Stack Overflow](https://survey.stackoverflow.co/2026/ai/data)). JetBrains' 2026 survey of 15,000+ professional developers found **90% use an agent weekly, 68% daily**, with Claude Code at **39% at work**, Codex at **16%**, Copilot at **21%**, Cursor at **12%** and OpenCode at **7%** ([JetBrains](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)). The gap between 66% using agents and 26% using agent workflows is precisely where freelance integration work lives.

Consolidation is now a structural feature, not a hiccup. **Roo Code was archived on 15 May 2026** with 492 open PRs. **Continue was acquired by Cursor in June 2026** and its repo went read-only. **Aider has had no commit since 22 May 2026** and carries 531 open PRs. **AutoGen has been maintenance-only since October 2025**, superseded by Microsoft Agent Framework. **SWE-agent** now warns that `mini-swe-agent` has superseded it. **Flowise** is archived ([Roo Code](https://github.com/RooCodeInc/Roo-Code); [Continue](https://github.com/continuedev/continue); [Aider analysis](https://aicoderscope.com/blog/aider-2026-stalled-what-happened-alternatives/); [AutoGen](https://github.com/microsoft/autogen/discussions/7066); [SWE-agent](https://github.com/SWE-agent/SWE-agent)). Healthy by observable signals: LangChain/LangGraph with an LTS policy and near-weekly patches, OpenHands with a peer-reviewed architecture and open benchmark harness, Cline, Kilo with **1,268 contributors**, Goose under foundation stewardship, and OpenCode with **900+ contributors** and very high release velocity ([LangChain release policy](https://docs.langchain.com/oss/python/release-policy); [OpenHands paper](https://arxiv.org/html/2511.03690v1); [Kilo](https://github.com/Kilo-Org/kilocode); [Ry Walker](https://rywalker.com/research/opencode)).

The skills layer is consolidating too, but around registries rather than projects. skills.sh is the de facto install registry, Anthropic's plugin marketplace is the highest-signal curated channel because partner listings are vendor-maintained, and the standards layer — agentskills.io plus the MCP Skills extension SEP-2640, which reached Final and merged on **13 September 2026** — is what makes skills portable across Claude Code, Codex, Cursor, Copilot, Gemini CLI and OpenCode ([skills.sh docs](https://www.skills.sh/docs); [MCP Skills extension](https://modelcontextprotocol.io/extensions/skills/overview); [SEP-2640](https://modelcontextprotocol.io/seps/2640-skills-extension)). Registry counts are large and mutually inconsistent: **60,909 skills and 45,833 plugins across 20 sources**, with 22,734 skills.sh entries and 7,400 ClawHub entries in one census ([Small Print](https://smallprint.dev/stats)). MCP has roughly **48,180 registry servers, 65% of them remote**, but only about **1,200 are genuinely evaluable** in a deep scan ([gravity.fast](https://gravity.fast/data/mcp-adoption-statistics/); [Major Labs](https://majorlabs.co/data)). Supply is not the constraint. Curation, security and integration are.

Benchmarks should not drive tool choice. SWE-bench Verified is officially topped by **Claude Opus 4.5 at 76.8%**, while Vals AI reports **97.0%** for a later model and Epoch reports **83.5%** — different harnesses, prompts, retries and subsets ([BenchLeader](https://www.benchleader.com/benchmarks/swe_bench_verified_any); [llmbenchmark.ai](https://llmbenchmark.ai/benchmarks/vals-swe-bench); [Epoch via AI.info](https://ai.info/tracker/benchmarks/swe-bench-verified)). SWE-bench Pro is worse: **89.9%** on one board versus **~23%** on another, unresolved ([BenchLM](https://benchlm.ai/benchmarks/swe-bench-pro); [Scale](https://labs.scale.com/leaderboard/swe_bench_pro)). On one controlled run, cost per resolved task varied **~10× ($0.097–$0.982)** among near-top systems ([Vibe Code Textbook](https://vibecodetextbook.com/posts/swe-bench-verified-task-by-task.html)). A private eval on 10–20 real issues from your target repo, run with that repo's own tests, is more predictive than any public leaderboard.

## A 76-skill library needs subtraction, not addition

Your setup — OpenCode with 76 global skills in `~/.agents/skills`, REA wired as an MCP server, Composio and Firecrawl installed — is already past the point where more skills help. The evidence says the binding constraints are retrieval precision, trigger reliability and context cost, not coverage. Claude Code budgets skill listings at **1% of the context window** and drops descriptions of least-used skills when the listing overflows; Codex caps the startup list at **2%** ([Voyager](https://voyager.so/blog/mcp-vs-skills)). GitHub's MCP server with all toolsets costs **91 tools and 40,117 tokens of definitions**; the default toolsets cost **46 tools and 19,150 tokens**; Notion's older self-hosted server cost **24 tools and 33,274 tokens** ([Voyager](https://voyager.so/blog/mcp-vs-skills)). Three to six MCP servers is the practical ceiling, because every write-capable server widens prompt-injection reach ([MCP.so](https://mcp.so/blog/best-mcp-servers)).

The stack that follows is deliberately small and mapped to jobs rather than categories.

| Layer | Keep / install | Job it does | Guardrail |
|---|---|---|---|
| Meta | `find-skills`, `skill-creator` | Find capability; capture your own process | Read `SKILL.md` and scripts before install |
| Project front door | `senior-dev-os` **or** the Superpowers chain — not both | Frames ambiguous work; loads the right sub-skills | One front door per session; avoid double triggers |
| Delivery discipline | `systematic-debugging`, `tdd`, `code-change-verification`, `verification-before-completion` | Root cause, failing test, real build/lint/test evidence | Never claim done without fresh output |
| Review | `requesting-code-review`, `receiving-code-review`, `understand-diff` | Self-review before a human or maintainer sees it | Critical findings block; verify feedback rather than agreeing |
| Client deliverables | `docx`, `pdf`, `pptx`, `xlsx`, `frontend-design` / `design-engineering` | Files and interfaces clients accept | Document licence forbids redistribution — never ship in a client repo |
| Design gate | `design-taste-frontend` + Figma MCP when designs exist | Art direction plus executable lint/inspect checks | Fix every FAIL, re-run; Figma write is beta-then-paid |
| Verification | `agent-browser` (or Playwright MCP + `webapp-testing`) | Snapshots, repro video, visual diff | Keep one browser stack only |
| Research | `research` + `firecrawl-*` (authenticate) + Exa | Citation-per-claim evidence with cost control | Primary sources beat aggregators; label estimates |
| OSS contribution | addyosmani pack: `code-review-and-quality`, `documentation-and-adrs`, `constraint-driven-development`, `doubt-driven-development` | Evidence gates and anti-rationalization | Check the project's AI policy first; one PR open |
| Business ops (later) | Notion, Stripe read-only, GitHub, Slack; Upwork MCP last | Admin and pipeline | Read-only first; 3–6 servers; no production credentials |

Sources: [skills.sh](https://www.skills.sh/docs), [Superpowers](https://github.com/obra/superpowers), [addyosmani](https://github.com/addyosmani/agent-skills), [MCP.so](https://mcp.so/blog/best-mcp-servers), [Voyager](https://voyager.so/blog/mcp-vs-skills), [Figma](https://developers.figma.com/docs/figma-mcp-server/).

Three deletions matter as much as three additions. Collapse the overlapping design entry points — `design-engineering`, `frontend-design`, `visual-ui-design`, `frontend-craft` and `design-critique` all compete to answer "make this look good" — behind one front door, and invoke specialists explicitly. Choose one process pack; running Superpowers and `senior-dev-os` and `mattpocock` discipline skills together produces duplicate triggers and a measurable regression tax. And drop novelty skills like `caveman` from the global set while keeping `stop-slop`, which has a real job on client-facing prose. The test of a skill is not whether it is good. It is whether it fires when needed and improves the output enough to justify its context and risk.

Two additions are worth more than the rest combined. First, an **`AGENTS.md` per project** containing the always-needed facts — build commands, test commands, conventions, forbidden actions, definition of done — because Vercel's eval showed an 8 KB index in the instructions file beating a documentation skill that failed to invoke 56% of the time ([Voyager](https://voyager.so/blog/mcp-vs-skills)). Second, a **private, pinned skill repository** with a review checklist: read the `SKILL.md`, list bundled scripts, check network calls, check dependencies, check licence, check maintainer and release cadence. With **36.82% of 3,984 audited skills carrying at least one issue** and **13.4% carrying a Critical one**, plus **76 confirmed malicious payloads**, install-time review is not paranoia ([Snyk](https://research.snyk.io/blog/agent-skills-threat-landscape/)). The ClawHavoc campaign published hundreds of malicious skills distributing the AMOS credential stealer, and CVE-2026-25253 was a one-click RCE in OpenClaw reached through auth-token exfiltration ([arXiv 2603.00195](https://arxiv.org/html/2603.00195v2)).

### The first 90 days: instrument, then productise, then specialise

| Window | Freelance track | Open-source track | Proof of completion |
|---|---|---|---|
| **Days 0–30** | Prune to ~20 active skills; write `AGENTS.md`; run one paid-discovery-style audit on your own RAG/agent project and publish the numbers | Read policies for five Tier 1 repos; land 3 triage/reproduction contributions; one PR open at a time | A measured before/after with a harness; 3 linked issue comments or merged fixes |
| **Days 31–60** | Package one offer — "agent/RAG evaluation harness audit" — with fixed scope, acceptance criteria and a paid discovery; publish 2 case studies with negative findings included | 5 merged PRs, at least 2 with regression tests; add the addyosmani review and constraint skills; build one private MCP server | Two inbound conversations; a merge history a maintainer can see |
| **Days 61–90** | Convert one audit into a retainer ($3K–$8K/month) or a fixed-fee build; add security/permissions scoping as an explicit line item | Contribute an MCP server or benchmark task to a project you use; review others' PRs; write up the workflow | One retainer or signed SOW; maintainer review activity; a reusable eval skill of your own |

The sequencing logic is evidence-driven. Focused skills with **≤3 modules outperform larger bundles**, and self-generated skills show **no average benefit**, so curation beats volume ([arXiv 2602.12670](https://arxiv.org/abs/2602.12670)). Explicit narrow descriptions and query-specific refinement recover much of the retrieval loss, which is why one front door per job beats five ([arXiv 2604.04323](https://arxiv.org/html/2604.04323v1)). Paid discovery and eval reports function as trust products because buyers cannot evaluate agent quality before purchase, which is why the first commercial artefact should be a measurement, not a build ([AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide)). And Upwork MCP belongs late, because automating proposals before the delivery loop is reliable just scales bad proposals ([MartechDB](https://martechdb.com/vendors/upwork)).

## What the evidence cannot tell you

The quantitative spine of this report is narrow and should be treated as such. Only two freelance sources are close to measurement: Upwatcher's crawler census of **5,536 postings** with explicit percentiles, and AgentScout's **690 scored postings** across Freelancer, LinkedIn, Reddit, Hacker News and RemoteOK. Both measure **posted budgets, not cleared contracts**. AgentScout's per-skill samples run as low as 10–96 postings, so its $38 Claude and React premiums rest on roughly 15–20 listings each and should not be over-read ([AgentScout](https://agentscoutjobs.com/rates)). Upwork's category rates are self-reported profile pricing, explicitly "directional benchmarks rather than hard rules" ([Upwork](https://www.upwork.com/resources/upwork-hourly-rates)). Upwork's own investor releases returned HTTP 403 during research, so its financials here are second-hand through GigRadar, which sells Upwork outreach automation and has an interest in framing the platform as a niche-selection problem ([GigRadar](https://gigradar.io/blog/upwork-market-report-2026)). The specialist bands of $180–$350/hour come from a job board's content marketing with no stated methodology ([AgenticCareers](https://agenticcareers.co/blog/freelance-ai-agent-developer-guide)). No platform publishes realised rates, take-home after fees, or agent-specific GMV.

Three widely repeated claims did not survive verification and are excluded as findings. Enterprise agent pilot-to-production failure rates of **86–88%** (with variants at 67%, 89% and 95%) trace to vendor content marketing with no primary survey — treat them as an unverified meme. The claim that OpenAI abandoned SWE-bench Verified over contamination is secondary and unconfirmed. And the **89.9% versus 23%** SWE-bench Pro discrepancy is unresolved rather than evidence about models. On the OSS side, the LF Research release summary was read but not the full report, so sample size, question wording and margin of error are unknown; the **25% slop** and **53% trust** figures are reported estimates, not measurements. The EASE study measures review *structure*, not defect escape rate or review quality. No public dataset ranks task types by merge rate, and no benchmark answers "would a maintainer merge this?" — the closest proxies are merge rate, review latency, comments per PR, revert rate and author responsiveness.

There are also genuine conflicts worth naming. The ASF holds that purely AI-generated output is generally not copyrightable while some projects, including yt-dlp and OpenTTD, treat AI code as unlicenseable; that legal disagreement is live and unresolved ([ASF](https://www.apache.org/legal/generative-tooling.html); [policy catalogue](https://github.com/melissawm/open-source-ai-contribution-policies)). Registry sizes disagree by an order of magnitude depending on deduplication method. Star counts for the same repo differed by **±30%** across aggregators on the same day. Claude Code's public repository may be an issue-and-docs surface rather than the agent's source, so its 152.9K stars should not be read as open-source adoption without qualification. And the security studies use different corpora — 3,984, 42,447 and 98,380 skills — so their percentages are not directly comparable. What is consistent across all of them is direction: a material minority of skills are unsafe, executable bundles are riskier, and marketplaces disclaim guarantees ([Snyk](https://research.snyk.io/blog/agent-skills-threat-landscape/); [skills.sh docs](https://www.skills.sh/docs)).

## Conclusion

The two markets are the same market with different payment rails. A freelancer sells verified uncertainty reduction to a client; a contributor donates it to a maintainer. Both pay in the same currency — a reproducible before/after, a test that fails then passes, a number someone can check — and both punish volume without judgment. That is why the highest-leverage artefact in this entire report is not a skill at all. It is an evaluation harness with a published negative finding, because it simultaneously serves as a freelance proof product, an OSS contribution, and the only reliable way to know whether the 76 skills you installed are helping.

The implication for sequencing is counterintuitive. The ecosystem's centre of gravity has moved to portable, cheap, advisory markdown, which means the marginal skill is worth less every month while the marginal *judgment* is worth more. Learn the substrate — MCP, `SKILL.md`, `AGENTS.md`, git-native review, eval design — then delete most of what you installed, instrument the rest, and let the evidence choose your niche. The people who will still be well paid in 2027 are not the ones with the largest skill library. They are the ones whose claims a client or a maintainer can verify in five minutes.
